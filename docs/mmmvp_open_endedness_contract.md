# UC-Bench MMMVP open-ended successor: construct-validity record

## Status and go/no-go rule

This is an unfrozen development successor. It preserves the earlier five scientific
conditions but replaces the answer-bearing task/checkpoint interface. No scientific
model call is authorized. The earlier frozen MMMVP and all of its results remain
immutable historical development artifacts.

The successor is locally eligible for a future compatibility stage only if every
gate in `artifacts/mmmvp_open_rc1/open_endedness_audit.json` passes. Any prompt, tool,
public metadata, schema error, example or log line that reveals a case defect,
preferred analysis, preferred resource, hidden outcome, belief direction or final
action is a no-go.

**Current result (2026-09-09): no-go.** The deterministic fixture controls pass, but
the independent implementation red-team found two blocking and four major unresolved
construct-validity defects. The machine audit therefore fails closed. See
`reports/generated/mmmvp_open_rc1_schematics_and_release_audit.md`. No compatibility,
scientific execution or freeze is authorized.

## 1. Exact agent-facing mission

> Assess the supplied predictor and evidence package for the stated intended use.
> Determine what can and cannot be concluded, perform the analyses you consider
> necessary, decide whether further evidence is worth purchasing within the budget,
> and recommend the appropriate next development action. Preserve the evidence
> supporting your conclusions.

That is the sole scientific instruction. The remaining agent-visible text is limited
to workspace/security rules, irreversible action mechanics, execution budget and the
machine-readable submission contract. The prompt does not name a metric, analysis
unit, defect, case, hidden condition, useful resource or acceptable conclusion.

## 2. Agent-visible surface

At reset the agent receives only:

- the neutral mission above;
- an intended-use file containing population, input time, endpoint, predictor output,
  action threshold and the immediate development decision;
- the evidence files naturally present in the diligence data room;
- the same neutral resource catalogue, returns, costs, delays and scope limitations;
- a network-disabled workspace with generic file inspection, reading, writing and
  command execution;
- `commit_validation_plan`, `reveal_validation`, `commit_followup_plan`,
  `purchase_resource` and `submit`;
- a generic schema that preserves the agent's own hypotheses, analysis plan,
  source-linked artifacts, calculations, findings, evidence eligibility, numerical
  belief updates, result-contingent actions, decision and claims.

The private case identifier cannot enter the prompt-builder signature. The serialized
messages and tool definitions are identical for all five conditions. The two Case 3
mechanisms have byte-identical public state until the committed purchase returns its
hidden result.

The catalogue includes plausible but unhelpful choices. It never says which defect is
present or which resource is preferred. `none` is a real action and can be correct.

## 3. Security and evidence boundary

The Docker container receives exactly one bind mount: the public episode workspace at
`/workspace`. It has no network, API key or private mount. Private truth, validity
cards, graders, sealed outcomes and unpurchased returns remain under host-only paths.
Outcomes or purchased evidence enter the public workspace only through the disclosed
irreversible action.

Commitments and event records are stored in a sibling host directory, not in a hidden
subdirectory of the mounted workspace. The verifier confirms the submitted objects
against those host records and their hashes. This closes a leak found during the
development audit: a dot-directory inside the mount would not have been a real
security boundary because shell commands could still discover it.

## 4. Workflow state and genuine choices

The environment enforces only irreversible boundaries:

```text
inspect/define hypotheses/plan freely
              |
              v
commit own validation plan  ---- immutable ----> reveal outcomes
              |                                      |
              +---------------- analyse freely -------+
                                                     |
                                                     v
                                      commit question, live explanations,
                                      resource and result-contingent actions
                                                     |
                                                     v
                                          purchase once (including none)
                                                     |
                                                     v
                                     analyse return, revise, decide, submit
```

It does not prescribe a ten-step checklist or stage order. The agent must independently
decide which records form the decision unit, which estimates matter for the intended
use, whether dependence or context changes the conclusion, whether evidence is valid,
which explanations remain live, whether a purchase has value and how its result changes
the decision. An unsupported correct label is insufficient because the underlying
analysis artifacts are independently checked.

## 5. Five private validity cards

| Condition | Professional purpose | Consequential ambiguity | Hidden/result-dependent choice |
|---|---|---|---|
| Case 1 | Decide whether clean-enough internal evidence earns bounded continuation | Repeated records and minor anomalies may or may not be material | `none` is valid when the immediate decision is resolved; replay is valid only for a declared reproducibility question |
| Case 2 | Determine whether impressive evidence represents independent people and stable contexts | Dependence, identity and context mixture compete | Reconciliation, external evidence or no purchase can each be valid for a different structured evidence target |
| Case 3 collapse | Contain circular preprocessing evidence and test a clean execution | Original performance is attractive but ineligible | Clean replay collapses; belief/action must follow the precommitted collapse branch |
| Case 3 remains | Audit the identical initial state without assuming collapse | No pre-purchase observation distinguishes it from the collapse variant | Clean replay retains bounded evidence; the agent must recover without restoring the contaminated result |
| Case 4 | Separate ranking from usable probabilities and action utility | Discrimination, probability accuracy, utility and transport answer different decisions | No purchase is correct for the resolved current-use question; external evidence is valid only if transport is the declared unresolved target |

The full private cards are in `grader_private/mmmvp_open/validity_cards.json`. Each
states the data-generating problem, professional decision, fair ambiguity, independently
recomputed properties, defensible alternatives, admissible target/resource policies,
unsupported claim scopes, first harmful failures, smallest corrective action and
intervention class.

## 6. Private grading method

Complete mission success is the headline. Partial scientific quality is the fraction
of decision-critical scientific properties passed; reliability and harmless contract
issues remain separate.

The verifier:

1. validates the disclosed generic schema without interpreting prose;
2. verifies irreversible event order, unique actions, commitment hashes and host
   records;
3. checks that the agent's own pre-reveal inputs and planned output paths were used;
4. resolves every artifact path, source link and optional hash;
5. reconstructs entity/source-record/prediction/outcome relationships from raw files;
6. independently recomputes conditionally relevant quantitative properties;
7. checks evidence eligibility from raw provenance rather than a reported diagnosis;
8. evaluates the structured evidence-target/resource pair against all privately
   admissible policies;
9. verifies the purchased return is in the final evidence chain;
10. checks numeric beliefs against committed baselines and directions, and checks the
    final action against the matched precommitted contingency;
11. evaluates only machine claim scopes/status and decision enums against verified
    evidence;
12. identifies the first decision-critical failure, consequence and smallest remedy.

No free-text statement, rationale, method name, allowed-use paragraph or final prose is
scientifically scored. Exact matching is limited to disclosed enums/IDs, paths, hashes
and source-data values. Unrecognized optional sensitivity results cannot invalidate a
correct primary analysis.

The score-source table and an AST-based duplicate/prose-access audit are embedded in
the generated audit artifact. Each mission-critical property has exactly one authority.

## 7. Local construct-validity controls

The zero-cost suite includes:

- one correct reference and a different valid workflow for every condition;
- every disclosed Case 2 target/resource alternative;
- valid `none`, justified abstention and bounded progression;
- unsupported correct action without analysis;
- always-advance, always-abstain, always-stop, always-buy and always-buy-nothing
  policies;
- a generic plan whose promised outputs are never implemented;
- a plausible but wrong confident decision;
- unnecessary purchase and premature abstention;
- copied Case 3 collapse output applied to the indistinguishable retained-signal
  variant;
- altered outcomes with copied calculations;
- one corrupted analysis row to verify nonzero diagnostic partial credit;
- natural professional paraphrases of every prose field;
- a deliberately wrong optional sensitivity value.

Reference and accepted alternatives must pass; negative controls must fail for the
corresponding scientific property; universal policies must fail somewhere rather than
being forced to fail in cases where they are genuinely correct.

These controls are necessary but not sufficient. They currently pass while the
release gate fails because the review demonstrated blind spots in typed quantitative
provenance, production-runner wiring, structurally distinct alternative workflows,
Case 3 replay causality, Case 2 identity reconciliation and Case 1 decision criteria.

## 8. Failure diagnostics

Scientific scoring and process annotation are separate. A failed mission records the
earliest consequential failure and downstream effects using these diagnostic families:

- wrong analysis unit or dependence handling;
- missed consequential data-integrity or provenance defect;
- invalid evidence admitted to the decision chain;
- decision-relevant quantitative analysis missing or wrong;
- weak separation of competing explanations;
- dominated resource purchase or unnecessary escalation;
- precommitment/action mismatch;
- belief/action not revised after result reveal;
- unsupported claim or overbroad use scope;
- justified abstention versus premature termination;
- incomplete artifact chain, copied constants or altered-input failure;
- contract, model-completion, provider and infrastructure failure (reported separately,
  never pooled into scientific zero).

Each diagnosis must cite a failed deterministic property and artifact/event evidence.
Training-data, prompting, SFT, RL or expert-remedy causes are hypotheses unless a paired
intervention directly demonstrates recovery.

## 9. Candidate panel and execution pause

The authenticated read-only catalogue confirms the ten exact candidate model IDs in
`configs/uc_bench_mmmvp_open_model_panel.json`. GPT models are strictly earlier than
5.2 and Claude models strictly earlier than 4.5. GPT-5.2/5.4/5.6, Astra, Claude 4.5+
and all held-out models are excluded.

No candidate has passed a compatibility canary for the open successor. A prior canary
on the old frozen interface does not substitute for this gate. Compatibility, sentinel,
full-matrix execution, balance checks and cost re-estimation are all paused until the
construct-validity gate passes. No account change is authorized by this review.

## 10. Remaining construct-validity limitations

- These are internally authored synthetic controls, not external specialist validation.
- Five conditions are a calibrated pilot/case study, not a broad biology benchmark.
- No model has seen the successor, so difficulty and model differentiation are unknown.
- Numerical alternative acceptance is currently too narrow: enumerated source-table
  variants do not establish acceptance of a genuinely distinct repeated-measures,
  hierarchical or other dependence-preserving workflow. This is a major release defect.
- Quantitative property checks currently harvest unlabeled numbers and do not prove that
  the declared code generated the output. This is a blocking reward-hacking route.
- The resource-value grader uses structured evidence targets because free-text semantic
  judgment is deliberately excluded from headline scoring. Rich prose can support
  diagnostics but cannot rescue an unsupported machine action.
- One attempt per model would remain calibration only. Repeated attempts and uncertainty
  are required before any ranking claim.

These limitations are disclosed constraints, not reasons to reintroduce answer-bearing
instructions.
